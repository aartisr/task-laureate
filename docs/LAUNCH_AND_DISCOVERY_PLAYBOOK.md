# Launch and discovery playbook

This is the human-operated companion to the repository's technical discovery work. It is designed to earn useful references and qualified visitors, not to manufacture links or promise rankings.

## Before announcing

1. Deploy the current commit.
2. Confirm `https://tasks.ai-aarti.com/`, `/about/`, `/support`, `/robots.txt`, `/sitemap.xml`, `/llms.txt`, and `/og-image-v2.png` return `200`.
3. Test the production URL in link-preview debuggers for the channels you plan to use. Social networks cache previews independently, so refresh their cache only after the final image and copy are deployed.
4. Confirm the GitHub Pages overview at `https://aartisr.github.io/task-laureate/` links to the current production URL.

## Search ownership and measurement

These actions require the domain owner's accounts and cannot be performed from source code.

1. Verify `tasks.ai-aarti.com` in [Google Search Console](https://search.google.com/search-console/about) and [Bing Webmaster Tools](https://www.bing.com/webmasters/).
2. Submit `https://tasks.ai-aarti.com/sitemap.xml` to both.
3. Inspect `/` and `/about/` in Google Search Console after each public-content release. Record the Google-selected canonical and any crawl/indexing reason.
4. Review monthly: indexed pages, referring domains, queries, mobile usability, Core Web Vitals, and broken links. Improve pages that earn impressions but not clicks with clearer titles and visible answers—not keyword stuffing.

## GitHub and trusted profile links

Set these once in GitHub's repository settings and profile UI:

- Repository **Website**: `https://tasks.ai-aarti.com/`
- Repository description: a concise, factual product sentence matching the public page.
- Repository topics: `task-manager`, `productivity`, `react`, `typescript`, `vite`, `supabase`, `open-source`, `accessibility`.
- Pin the repository on the author profile and link the production app from the profile website/bio where appropriate.
- Keep the README's live-app link, GitHub Pages overview, contributor guide, and release notes current.

## Earn references by being useful

Publish one small, original item per meaningful release, such as:

- A short release note that explains a real user benefit with a screenshot.
- A guide to task dependencies without overload.
- A transparent write-up of private attachments or row-level-security design.
- A student or maker planning template that can be copied and adapted.

Share each item only with communities where it directly helps: your school/community, relevant open-source lists, developer forums, accessibility or productivity groups, and personal professional profiles. Link to the most useful page for that audience, not always the home page.

Never buy links, automate comments, create fake reviews, scrape contact lists, cloak content, or mass-submit low-value directory listings. Those tactics weaken trust and can suppress visibility.

## Success criteria

The first durable signals are not a viral view count. Look for:

- Valid indexing and a stable selected canonical.
- Search impressions for accurate task-management and open-source queries.
- References from people who actually use, review, teach, or build with the project.
- Returning visitors, useful issue reports, contributors, and successful activations.

AI-assisted search visibility follows the same pattern: a crawler-accessible, accurate, well-linked page with visible factual content is eligible to be discovered; no tool can compel an AI system to cite it.
